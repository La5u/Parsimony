Parsimony

How much code do coding agents write to fix real issues? Research preview.

Parsimony measures published SWE-bench Verified patches in coding units: each statement, call, comparison, name and literal counts as one unit. Formatting, comments and punctuation are not counted. Patches that pass the tests score higher when they are smaller. Failed patches score zero or below.

Rank Model

Rank is by net units added, lowest first: a 10% trimmed mean over measured in-scope attempts—including failures—that drops the most extreme 5% at each end so a few mass deletions cannot decide rank alone. Equal values tie; models with no measurements are unranked. Partial coverage can change the order. This is smallest measured footprint, not best coding ability.

Each task was run four times; every measured attempt contributes to its model’s footprint.

Method

  • Each patch is applied to the task's base commit and both versions of each changed file are parsed. Nothing is executed.
  • Footprint rank uses a 10% trimmed mean of net coding units added across all measured, in-scope attempts: the lowest and highest 5% of each model’s attempts are dropped (none when a model has fewer than 20). Successful and failed attempts both count; passing references are not required. The plain mean remains available as a graph metric.
  • Correctness is reported separately by the upstream benchmark. Smaller failed or no-op attempts are not better solutions.
  • Test, docs and generated files are excluded. Only Python is measured.

Limits

  • Smaller is not always better. Units measure size, not readability or design.
  • Scores are relative to the reference models, which all use the same agent harness (mini-SWE-agent).
  • Pass/fail comes from SWE-bench's published results; tests are not rerun.
