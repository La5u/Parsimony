SWE-bench Verified · 500 tasks

Solving the issue is the minimum. How much code did it take?

Parsimony takes public SWE-bench Verified patches and counts the coding units each fix adds and removes: statements, calls, comparisons, names and literals. Only patches that pass the tests earn credit, so the benchmark rewards correct solutions with the smallest footprint.

Method

How a patch becomes a score

Nothing is executed or rerun. Parsimony downloads published patches and evaluation results, applies each patch to the exact base commit in memory and compares the code before and after.

Correctness gate

Only passing patches earn credit

A task counts as solved only if SWE-bench's published evaluation says so. Explicitly failed patches get a penalty for the code they added. Anything unknown stays unknown and is never treated as zero.

Coding units

Count what a reviewer reads

Each file is parsed into a syntax tree. Every statement, call, attribute, comparison, name and literal is one unit, and each block adds one unit for its nesting. Formatting, comments, docstrings, brackets and name length are free. Tests, docs and generated files are out of scope.

Per-task percentile

Compare against every solver of that task

On each task, a solution is ranked against all successful patches from the ten models. Net growth (units added minus removed) weighs 70% and churn (added plus removed) 30%, so a big rewrite cannot hide behind a small net change.

success = 1 + 99 × (0.7 × p_net + 0.3 × p_churn)
Equal task weight

Average over every task

Failed attempts score from −25 to 0 depending on how much code they added. The score is the mean over all tasks, so a small fix counts as much as a large feature. It runs from −25 to 100, and 50.5 means average among the ten solvers.

failure = −25 × (0.7 × growth + 0.3 × churn burden)

Limits

Read these before quoting a number

  • Small is not the same as good. Units measure size and nesting, not readability, design or safety. A patch that hardcodes a test input can cost fewer units than a general fix.
  • Scores are relative to these ten models. The reference panel is the ten submissions themselves, so a score says how a model compares with this group, not with an ideal patch.
  • One harness only. All ten submissions use mini-SWE-agent v2.0.0, published 2026-02-17. Other harnesses and prompts can change footprint a lot.
  • Many tasks are ties. Most Verified fixes are tiny and have essentially one solution, so the ranking is driven by a minority of tasks. The interval shows how much ranks could shift.
  • Correctness is taken as published. Parsimony trusts SWE-bench's evaluation and does not rerun tests. Deleting untested code is not detected.
  • Python implementation files only. Test, doc, example, vendored and generated files are excluded, and other languages are not measured.
