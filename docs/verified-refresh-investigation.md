## Model coverage and blockers

- **Gemini 3.5 Flash (mini v2.4.2)** is genuinely new model coverage relative to the 33-model panel. Pinned metadata is publicly readable (SHA recorded in the evidence JSON); pinned `per_instance_details.json` is also readable with 441 task records (359 explicit `resolved: true`, 82 `false`). The metadata reports 71.8%, corresponding to the 359 solved records over the 500-task cohort. The public run repository contains logs/patches outside the official submission bucket. Representative explicit passing and failed outcomes each had an accessible `patch.diff` in that repository; response hashes are recorded. This establishes public partial artifacts, not complete 500-task patch availability or a completed footprint measurement. The remaining 59 tasks have no record in the details file; no outcome is inferred for them.
- **GPT-5.2 Codex (mini v2.0.0)** is also a distinct model not in the 33, and metadata is public (reports 72.8% resolved). However, pinned `per_instance_details.json` and `results.json` probes both returned 404. Metadata points to S3 logs/trajs but no public per-task result artifact was found by these probes. This is an artifact blocker, not evidence of failure.
- **Claude 3.7 Sonnet** has public pinned per-instance details for all 500 instances (51 explicit resolved, 449 unresolved). Metadata points to S3 logs/trajs. The first explicit passing and unresolved instance patch probes at the corresponding pinned raw-GitHub paths returned 404. This does not prove those patches are absent from S3; the README's reported 402 missing patches remain the coverage blocker. `resolved: false` is an outcome signal, not a patch-availability measurement.
- **Gemini 3 Pro high** has 500 explicit `resolved: false` entries in the per-instance file, conflicting with metadata's reported 69.6%. This inconsistency is preserved, not reconciled or treated as a cohort result.
- The other newly distinct old-model exclusions have public metadata, while the requested raw per-instance/results paths returned 404 in this check. Several carry S3 asset pointers. Missing files here are not failed runs. The five duplicate-version exclusions do have public per-instance details, but are version checks rather than new model coverage.

All successful-response SHA-256 values, exact artifact URLs and HTTP statuses are in the JSON evidence file. Requests used `Cache-Control: no-cache` and `Pragma: no-cache`; 404 means only that the requested URL/path was not served. No conclusion is drawn from artifact absence alone.
