# Repository audit and release-readiness review

This is a working-tree audit, not independent benchmark certification. It covers the analyzer and language workers, artifact/cache/snapshot handling, importers and preimage checks, CLI resume, contributions, scoring and release validation, statistical diagnostics, external-index ingestion, site generation, browser interaction, packaging and CI. Public model discovery was refreshed separately. No model API calls, benchmark reruns or submitted-code execution were performed.

## Confirmed issues addressed

- **Integrity and recovery:** resume keeps retry evidence until submission provenance has been checked; snapshots validate member types and sizes and clean up unique temporary files; manifests and importer inventories reject malformed/ambiguous identities, duplicate keys and unsafe paths where covered by regression tests.
- **Provenance:** standalone Live patch hashes are checked before analysis; DeepSWE retains the fetched release hash; preimage audits reject mixed unsupported blocks and ambiguous index metadata rather than silently overlooking them. These checks do not certify historical evaluator state or backend identity.
- **Analysis reliability/performance:** bounded Myers alignment skips impossible length imbalances and handles empty sides directly; wide TypeScript trees avoid JavaScript argument-count limits; worker initialization and exchanges are serialized and shutdown reaps failed workers.
- **Iterator correctness:** leaderboard, snapshot creation, scoring and diagnostics preserve one-shot inputs instead of consuming them before use. Shared prediction exports are parsed once per snapshot scan; site agent lookup and diagnostic bookkeeping avoid repeated work.
- **Validation:** invalid metrics, resolve rates, reference bases, population totals, statistical parameters and external-index values are rejected. Out-of-scope detection uses actual file paths, not equal list lengths.
- **Diagnostic uncertainty:** sensitivity resampling now keeps repeated attempts for the same task together. This corrects the sampling unit; regenerated diagnostic intervals can change. Existing published reports are unchanged and must not be described as having been regenerated by this audit.
- **Security:** Artificial Analysis requests refuse redirects carrying the API key and bound response size. Imported browser JSON remains text, not executable HTML; upload races, errors and clearing are tested.
- **Professional UI:** missing solved outcomes stay missing, fractional bar values and failure disclosures are retained, keyboard sorting retains focus, Escape dismisses tooltips, document metadata is in a valid head, boards have distinct titles and navigation, and disabled JavaScript has an explanatory fallback.
- **Release tooling:** networked verification pins Python 3.14.7; CI checks that the distributable wheel contains the CLI and Node parser worker without bundling tests or benchmark artifacts.

## Frozen-release protections

The frozen measurement JSONLs, populations, reference panels, external snapshots and published diagnostic files were not rewritten. All six website pages were rebuilt; their embedded data payloads were unchanged. Ranking remains the plain mean over measured in-scope passing and failed attempts, with missing data excluded and a separate solved-only column. No coverage gate, correctness tie-break or trimming was introduced.

Code changes alter the analyzer source identity even when counts are preserved. Do not relabel old records, resume old analyses with the changed checkout, or merge newly measured inputs into a frozen cohort without checking identity/compatibility. Measure from a clean committed, versioned checkout. This audit does not authorize raw-artifact redistribution.

## 2026-10-12 follow-up

Resolved in analyzer 0.9.0-beta: strict hunk-header/surplus-line rejection and duplicate implementation-section rejection (the former High findings), prefix-free binary/rename scope checks, spec-conformant `empty_patch` scoring, leaderboard out-of-scope exclusion, interpolated bootstrap quantiles, bounded downloads and snapshot restores, public-HTTPS contribution URLs, workflow input/SHA pinning, undrained worker stderr and mixed analyzer-source detection. A re-fetch of all 20,621 published Verified/Live patches found no newly rejected measurement. See the [changelog](../CHANGELOG.md). Still open: the items below, worker deadlines, and restoring snapshots only from trusted sources (manifest hashes prove self-consistency, not authenticity).

## Validation and reproduction

Use Python 3.14.7 for measurement comparisons, TypeScript 5.9.3 (`npm ci`), and the Go pins in `pyproject.toml`. The ordinary suite permits missing optional parsers; such a run is not a full-parser validation.

```sh
python -m unittest discover -s tests -q
node tests/custom_benchmark.cjs
for page in index javascript typescript go verified live; do
  node tests/site_sorting.cjs "site/$page.html"
done
python -m parsimony.contribute validate submissions
python -m parsimony.scoring score examples/ten-model-score-panel.json \
  examples/ten-model-results.jsonl --output /tmp/parsimony-scores.json
cmp examples/ten-model-scores.json /tmp/parsimony-scores.json
git diff --check
```

Validation at the original audit: **345 Python tests collected, passing with 6 opt-in browser skips** in the pinned-parser environment; **6 real Firefox tests passed** separately; all six Node page checks and importer checks passed. Wheel contents were verified, contribution validation found zero bundles, and both the historical ten-model and current Live score files reproduced byte-for-byte. `git diff --check` passed. HTTP-error fixture/driver cleanup emitted resource warnings, not test failures. The CI matrix itself was not run locally.

Real Firefox checks are opt-in (`PARSIMONY_BROWSER_TESTS=1`) and require Selenium, Firefox and geckodriver; see `tests/test_site_browser.py` and the browser audit for the tested versions. They are not a WCAG conformance test. Offline integrity tests and published arithmetic comparisons do not authenticate upstream correctness claims.

This review intentionally leaves the project labelled beta/research prototype. Better engineering and test coverage do not turn an exploratory footprint comparison into an official coding-quality ranking.
