## Fresh-artifact spot check and problems found

Five deliberately chosen diagnostic tasks were fetched into a **fresh** URL cache, their patch and result SHA256s compared to the records, and their measurements recomputed against newly fetched base files. All five matched the recorded results or recorded failure: `django__django-13109` (identifier-only success), `astropy__astropy-8872` (identifier/literal-only failure), `django__django-13012` (excluded-path success), `pallets__flask-5014` (ordinary success), and `django__django-13513` (context error). This reuses the **same analyzer**, so it is an artifact/recomputation spot check, not an independent metric implementation or a correctness evaluation. Source file hashes are in `recheck.json`.

**Important exclusion defect discovered:** the `0.2.0-beta` generated-file heuristic scanned prose anywhere in the first 2,000 characters. It excluded real implementation files, for example `django/db/models/expressions.py` because a comment says operators are “generated by .bitand()”, and `sklearn/compose/_column_transformer.py` because a docstring says features are “generated by each transformer”. The project also excludes `django/db/migrations/` by path, even when a task modifies migration *implementation*. Thus low or zero primary churn can mean a scope omission, not a small fix. The generated-file heuristic has been tightened in the subsequent `0.2.1-beta` code; the path-scope policy still requires review. **Do not use this `0.2.0-beta` run to rank models.** Reanalyze on a newly frozen analyzer version before comparing submissions.

Next gate: validate the revised inclusion rules against adversarial/real patches, regenerate this full cohort with a new manifest, inspect the remaining failed-patch error, then analyze a second submission on the identical frozen task population. Independent evaluators must still check published correctness and sample raw patches; a local recomputation alone is insufficient.
